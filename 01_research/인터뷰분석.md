# 인터뷰 분석

| 구분 | PP1 · 재작성 이탈 | PP2 · 유보 스크랩 | PP3 · 조건 선스캔 |
|---|---|---|---|
| **원문** | R1 "이력서/프로필을 새로 작성해야 해서" (버튼 누른 뒤 그만둠)<br><br>R2 "예전에 다른 직종 알바에 맞춰 적어둔 게 있어서 고치기 귀찮았어요"<br><br>(대조) R1이 실제 지원한 공고 → "지원 절차가 간단했다" | R2 "사업장이 엄청 가까웠던 것도 아니라서, 간절함이 없었어요" / "더 가까운 곳 올라오면 그때 지원해야지" / "스크랩·저장만 해뒀다"<br><br>R1 "조건이 그냥 나랑 안 맞아서" → 직후 "다른 앱에서 비슷한 공고를 찾아봤다" | R1 공고 열고 가장 먼저 확인 = "근무 시간/요일"<br><br>R2 "확인한 건 근무 시간/요일이지만 그 이전에 위치기반으로 필터링을 했습니다"<br><br>R2 지원한 공고 결정적 이유 "가깝고 일도 쉬워 보임" |
| **그룹화** | **지원 직전의 서류 마찰**<br>· 버튼 이후 새 서류/프로필 요구<br>· 기존 이력서를 직종에 맞게 고치는 수고 | **노력 대비 매력 부족 → 미룸**<br>· 조건·거리가 지원 수고를 정당화 못 함<br>· 이탈 즉시 대체 공고 탐색·스크랩 | **스케줄·입지 적합성이 첫 관문**<br>· 공고 판단 전에 시간·거리부터 걸러냄<br>· 미스매치면 지원 의지 자체가 사라짐 |
| **인사이트** | 사용자는 공고 내용이 아니라 **'버튼 이후의 서류 작성 노동'**에서 이탈한다. | 지원에 드는 수고(서류·절차)가 일정할 때, 공고의 매력(조건·거리)이 그 수고를 넘지 못하면 **'지금 말고 나중'**으로 미룬다. | 사용자는 공고를 '읽기' 전에 **근무 조건·거리로 먼저 필터링**하며, 이 적합성이 이후 이탈/지원을 좌우한다. |
| **키워드** | **재작성 이탈**<br>이력서를 다시 쓰다가 / 반복 입력 부담 | **유보 스크랩**<br>저장만 하고 미루다 / 간절함 < 지원 수고 | **조건 선스캔**<br>열자마자 시간·거리부터 훑다 / 미스매치 시 즉시 이탈 |
| **아이디어** | 프로필 자동 채움 · 직종별 이력서 **원클릭 전환** | '내 조건(거리·시급) 부합도 점수' + 스크랩 공고에 더 나은 대체 공고 알림 | 내 가능 시간·통근거리 기반 자동 매칭 배지를 공고 최상단 고정 (예: "내 조건 92% 부합 · 도보 8분") |
